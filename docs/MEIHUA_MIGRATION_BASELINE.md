# 梅花易数迁移基线

## 上游与范围

- 上游：mingyu `0.4.0`
- 核心入口：`packages/core/src/divination/algorithms/meihua/index.ts`
- 起卦方法实现：`helpers/methods.ts`
- 卦象与体用辅助：`helpers/hexagram.ts`
- Flutter 算法版本：
  - `meihua v1 / shaoshi-number-random-core-v1`
  - `meihua.time v1 / lunar-year-month-day-china-civil-hour-v1`

当前支持：

1. 时间起卦：农历年支、农历月日和中国民用时支。
2. 数字起卦：数字 + 时支序。
3. 随机起卦：三个随机整数分别确定上卦、下卦和动爻，支持 seed/replay。

暂不支持：声音、字数、方位和 `timeTrigram` 兼容入口。

## 时间法历法口径

时间法使用农历年支、农历月、农历日和时支：

```text
上卦 = (年支序 + 月 + 日) % 8
下卦 = (年支序 + 月 + 日 + 时支序) % 8
动爻 = (年支序 + 月 + 日 + 时支序) % 6
```

当前已明确并实现：

- 默认时区为 `Asia/Shanghai`，输入墙上时间不随设备时区变化。
- 年支取农历年干支，以正月初一换年；立春干支年只保存为历法证据，不参与取数。
- 农历月日由 `lunar` 计算，闰月沿用同名月序。
- 时支按当地民用钟表时间，23:00 为子时，但日期到 00:00 才切换。
- 真太阳时不进入默认时间法，未来如需支持必须另立规则版本。

共享输入由 `DivinationCalendarSnapshot` 生成，同时保存农历取数字段和节气干支字段，防止两套年界被混用。

- prompt、AI 文案和现代解释不进入 v1。
- 月令旺衰、应期和阶段趋势等依赖历法或解释规则的内容后续独立版本化。

## 向量说明

`test_vectors/meihua/v1.json` 中：

- 数字 123 的主互变和动爻来自 mingyu 上游回归测试。
- 数字 1 的“用生体”来自上游回归测试，并按同一公开换算规则补齐三卦字段。
- 随机向量使用项目已与 mingyu 对齐的随机算法，锁定三个随机样本及完整卦盘。

`test_vectors/meihua/time_v1.json` 锁定上游关键回归：2024-02-05 已过立春但尚未到春节，节气干支年为甲辰，时间起卦仍以农历癸卯年的卯支入数。

`scripts/reference/export_meihua_mingyu.mjs` 已准备为黑盒导出入口，但本地 mingyu 尚未安装 `tyme4ts` 等 Node 依赖，当前不能直接执行完整 `generateMeihua`。安装上游依赖后应重跑脚本并逐字段复核 fixture。

## 现代白话解释层

`meihua.local-reading v1` 已与核心算术分离。它只读取保存后的主卦、互卦、变卦、动爻和体用关系，生成传统概览、当前处境、内部过程、变化趋势、行动建议和风险提醒。解释内容随历史载荷保存，未来文案升级不得用新规则重写旧记录。
