# mingyu 项目分析与可复用边界

> 基准仓库：`githubsm/mingyu`
>
> 当前分析版本：`mingyu 0.4.0` / `mingyu-core 0.4.0`
>
> 目标项目：Flutter `zhaoxingzhai`
>
> 本文用途：确定 mingyu 中哪些内容可作为行为基准、哪些可以通过兼容依赖复用、哪些必须独立实现，以及如何验证 Flutter 结果。

## 1. 项目定位

mingyu 不是单一网页，而是一套完整的术数计算与 AI 接入工程，主要包含：

- `packages/core/`：可发布的 `mingyu-core` 核心算法包。
- `src/`：React/Vite Web 产品。
- `functions/`、`server/`：REST API 与服务端运行层。
- `mcp/`、`packages/mcp/`：MCP 服务。
- `skills/mingyu/`：Agent Skill。
- `android/`：Capacitor Android 容器。
- `tests/`：算法、API、浏览器、集成和 MCP 测试。
- `scripts/`：构建、数据生成和审计脚本。

`zhaoxingzhai` 主要需要研究的是 `packages/core/src/`，而不是复制 mingyu 的 React 页面、服务端或 Capacitor 工程。

## 3. mingyu 实际使用的第三方底座

mingyu 并非所有能力都从零实现。迁移时必须追踪真实依赖，不能只看它暴露的函数。

| 依赖 | mingyu 中的用途 | Flutter 策略 |
|---|---|---|
| `tyme4ts` | 农历、干支、节气、黄历基础 | 当前使用 `lunar`；历史时区使用 `timezone`，补充差异测试 |
| `iztro` | 紫微斗数 | 查找许可兼容的 Dart 实现，或将紫微作为独立服务能力 |
| `caelus` | 西方占星和星历 | 不移植其 TypeScript 包装；寻找可靠 Dart/native 星历引擎 |
| `astronomy-engine` | 七政四余所需天体位置 | 使用成熟星历库或服务端计算 |
| `@soul-atelier/xuankong` | 玄空相关能力 | 单独检查许可证与 Flutter 替代方案 |

第三方库的许可证独立于 mingyu。即使某项由 mingyu 调用，也需要分别检查该依赖能否在 Flutter 项目中使用。

## 4. 本项目采用的复用原则

本项目当前采用“行为参考 + 独立 Flutter 实现”的路线，而不是逐行翻译 mingyu 源码。

基本链路为：

```text
公开传统规则或兼容第三方库
        ↓
编写不含 mingyu 代码表达的功能规格
        ↓
用 Dart 重新设计数据模型和算法
        ↓
运行 mingyu 生成黑盒输入输出向量
        ↓
逐字段比较并记录差异原因
```

结果可以一致，但 Dart 文件结构、函数拆分、变量名、注释、错误文案和数据表达不能只是 TypeScript 的改名翻译。

## 5. 可以复用或复制的内容

这里的“可以”仍以对应内容确实属于公开事实、公开标准、自有内容或许可证兼容为前提。

### 5.1 可以作为产品规格直接记录

- 支持哪些术式。
- 每种术式需要哪些输入字段。
- 每种术式输出哪些结构化字段。
- 哪些功能需要出生案例、经纬度、时区或真太阳时。
- 哪些页面支持手动起卦、随机起卦或指定结果。
- 算法应处理哪些边界条件。
- 哪些模块需要延迟加载。
- 哪些结果应保存算法版本和随机轨迹。

这些属于功能和接口层面的事实，可以整理为本项目自己的规格。

### 5.2 可以采用的通用算法和公开规则

- Fisher–Yates 洗牌。
- FNV-1a 等有公开规范的哈希算法。
- PCG、Mulberry32 等有公开规范的伪随机算法。
- 公历、农历、干支、五行等公开规则。
- 六十四卦编号和卦象等公共事实。
- 八卦、天干、地支、五行生克等传统基础关系。
- 公开文献能够独立确认的小六壬、梅花、六爻等数学规则。

实现时应引用公开规范或传统资料，而不是引用 mingyu 的具体代码表达。

### 5.3 可以生成的黑盒测试向量

可以运行 mingyu 后记录：

- 输入。
- 输出结构。
- 关键字段值。
- 错误类型。
- 边界场景表现。
- 性能基线。

测试向量应保存为与实现无关的 JSON，例如：

```json
{
  "caseId": "xiaoliuren-001",
  "input": {
    "dateTime": "2026-09-17T14:30:00+08:00",
    "rule": "standard"
  },
  "expected": {
    "lunarMonth": 8,
    "lunarDay": 7,
    "hourBranch": "未",
    "resultPalace": "赤口"
  }
}
```

测试向量不能只依赖 mingyu；关键边界应再由公开资料、人工手算或独立库复核。

### 5.4 可以借鉴的工程思想

- 算法、evidence、Prompt 分层。
- 重型模块动态加载。
- 结果携带来源、版本与限制信息。
- 随机结果支持 seed 和 replay。
- 能力注册表描述输入要求和可用状态。
- 对时区、节气和真太阳时进行显式建模。
- 使用 exhaustive tests 覆盖年份、日期和组合空间。

这些思想应按 Flutter 架构重新实现。

## 6. 不能直接复制、必须独立处理的内容

### 6.1 源代码表达

在闭源或非 AGPL 路线下，不直接复制：

- TypeScript 函数体。
- 相同的条件分支排列。
- 只改变量名或语法的 Dart 翻译。
- 原有文件拆分和类结构的机械映射。
- 注释、错误文案和说明文本。
- 测试代码的逐行翻译。

### 6.2 人工整理的数据和文本

以下内容不能默认视为无版权数据：

- 三山国王灵签的现代解释和典故整理。
- 塔罗牌义、正逆位解释和关键词组合。
- 雷诺曼解释文本。
- 奇门、大六壬等格局断语。
- 古籍校勘、标点和现代释义。
- 姓名字典的释义、分类和人工标签。
- Prompt 和 evidence 中的完整自然语言文本。

传统原文可能属于公共领域，但现代标点、选编、整理和解释仍可能具有独创性。需要重新查找来源、校勘和编写。

### 6.3 大型静态表

不能直接把以下 TypeScript 数据表改成 JSON 后当作独立实现：

- 奇门格局表。
- 康熙字典与姓名数据。
- 地区树。
- 灵签完整现代解释。
- 古籍结构化语料。
- 人工整理的术式证据表。

应逐项确认数据来源、许可和是否存在公共数据替代。

## 7. AGPL 对本项目的影响

mingyu 与 mingyu-core 标注为 `AGPL-3.0-only`。

如果直接复制、修改或翻译 mingyu 的受保护源码，并将其组成 Flutter 应用对外分发，通常需要按 AGPL 履行对应源码提供义务。通过网络提供修改后的 AGPL 程序也可能触发源码提供要求。

因此本项目确立：

1. 不把“能看到源码”等同于“可以闭源复制”。
2. 默认不逐行翻译 mingyu。
3. 算法首先依据公开规则、标准和兼容依赖独立实现。
4. mingyu 用于能力分析、行为对照和测试向量生成。
5. 如果未来决定整个项目采用 AGPL，则可重新评估直接移植范围。
6. 如果需要直接使用独有算法或数据，可联系权利人取得额外授权。

本文是工程合规约定，不构成正式法律意见。

## 8. Flutter 替代映射

| mingyu/TypeScript 能力 | zhaoxingzhai 实现 |
|---|---|
| `Date` 与本地时区 | `DateTime` + 显式 UTC/时区模型 |
| `tyme4ts` 农历 | `lunar`，并用差异向量验证 |
| IANA 历史时区 | `timezone` |
| `Math.imul` | Web 安全的 16 位拆分 `_imul` |
| `crypto.getRandomValues` | `Random.secure()` |
| 动态 `import()` | 功能仓库和数据按需初始化 |
| Web Worker | `Isolate.run` 或 `compute` |
| 大型 TS 常量 | 来源合规的分片 JSON/数据库 |
| localStorage | SharedPreferences + 数据库 + 安全存储 |
| 可取消 Promise | 请求序号、CancelableOperation 或流取消 |

## 9. 每个算法模块的准入流程

每个术式进入 Flutter 前必须完成：

1. 写明用户功能和输入输出。
2. 列出公开规则与资料来源。
3. 标记 mingyu 相关入口，仅用于对照。
4. 列出第三方依赖和许可证。
5. 编写独立规格，不包含原源码表达。
6. 用 Dart 纯函数实现核心计算。
7. 建立正常、边界、非法输入测试。
8. 生成 mingyu 黑盒向量进行比较。
9. 对不一致结果给出明确解释。
10. 写入 `algorithmId` 和 `algorithmVersion`。
11. 评估 Web/Android/iOS 数值语义差异。
12. 评估数据体积和内存上限。

## 11. 当前已确认可落地的内容

| 内容 | 决定 |
|---|---|
| mingyu 的功能目录 | 可整理进本项目规划 |
| 输入输出字段与能力边界 | 可作为规格参考 |
| 黑盒结果 | 可生成测试向量 |
| 公开传统公式 | 可依据独立来源实现 |
| 通用随机/洗牌算法 | 可依据公开规范实现 |
| 动态加载、版本化、回放思想 | 可在 Flutter 中重建 |
| mingyu TypeScript 函数体 | 默认不直接复制 |
| Prompt、解释文本、错误文案 | 重新编写 |
| 大型人工数据表 | 逐项核验来源后决定 |
| React、API、MCP、Capacitor 代码 | 不迁移到 Flutter 核心 |
