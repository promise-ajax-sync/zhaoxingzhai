## 当前算法阶段

当前处于“公共算法基础 + 两个样板术式”阶段，还没有进入全量算法迁移阶段。

- 公共随机、版本、结果协议和历史追踪已经具备。
- 小六壬和塔罗证明了算法到 UI、案例快照、历史记录的基本链路可以工作。
- 灵签与每日一卦已继续复用同一套算法、数据、UI、历史和案例快照流水线。
- 八字、紫微、奇门、六壬、星盘等复杂系统尚未开始，不能按导航入口数量估算算法完成度。

## 优先级原则

算法仍是产品核心，但现阶段不应以“尽快增加术式数量”为最高优先级。近期优先级应为：

1. 保证现有随机、历法、版本和向量测试跨平台稳定。
2. 清理小六壬、塔罗的结构和数据来源，使其成为可复制模板。
3. 用一个低风险查表型术式打通数据导出、加载、算法、UI、历史和 golden 测试全链路。
4. 流水线稳定后，再提高算法扩展速度。

复杂算法在上述基础未稳定前提前铺开，会放大版本、数据来源、历法口径和跨平台差异的返工成本。
# 本地术式路由（2026-09-18）

- 已新增 `DivinationToolRouter`，覆盖当前可用的梅花易数、塔罗、小六壬、灵签和每日一卦。
- 路由优先识别用户明确指定的术式，其次根据地点/时间、人物心理、短期是否、综合指引和当天主题等高置信度规则推荐。
- 模糊问题返回未确定，不自动选择工具；后续 AI 路由只能作为此层的兜底。

## AI 解读服务层

- 已建立厂商无关的 `AiInterpretationService`，输入统一为原问题、结构化证据和本地回答。
- AI 只负责组织现代白话回答，不参与起卦、抽牌、排盘或算法结果修改。
- 提示词带独立版本号，明确要求输出直接回应、依据、反向信息、建议与能力边界。
- 提示词 v2 已拆分为自主维护的基础身份、安全边界、回答质量、回答风格和术式专属规则；现有梅花易数、塔罗、小六壬、灵签、每日一卦均有独立约束。
- 已提供本地结构化降级服务；远程服务异常、空回答或超时时自动回落，并记录降级原因。
- API Key 不进入 Flutter 客户端。真实模型接入必须经由后端代理，后续再实现具体后端适配器。
- 首页推荐进入梅花易数时，原问题会通过共享路由草稿自动填入占问主题，并本地推断感情、事业、财运、健康或学业分类。
- 塔罗已接入共享路由草稿、问题意图和 `DivinationEvidence`；现代解释升级为 `tarot.local-reading v2`，可针对人物、原因、趋势、行动、风险等焦点直接回应。
